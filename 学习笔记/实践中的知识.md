- 工具的“诊断输出”有层级：Error > Warning > Note。Warning 不等于“坏了”，只等于“可以更好”。 Homebrew 的 brew doctor 把“有更新可用”和“系统配置异常”都归在 Warning 里，但它们对“能不能正常装软件”的影响完全不同。**学会区分警告的严重程度**，比盲目追求“全绿”更能节省冲刺项目里的时间。
- “冲突”往往不是工具本身不兼容，而是默认行为的叠加造成了优先级混乱。 Anaconda 默认激活 base、把自己排在 PATH 最前面，这是为了方便“纯 Python 用户”；但当你同时是 Homebrew 用户时，这个“方便”就变成了“干扰”。解决这类问题的通用思路是：不要卸载工具，而是调整它们的默认行为，让每个工具只在被显式调用时生效。conda config --set auto_activate_base false 这一行命令，比卸载重装更能保护你的环境——因为它保留了隔离能力，只是把“什么时候隔离”的控制权还给了你。
- 安装命令其实因为文件被另一个 brew 进程锁住而中断了，所以 Node 24 并没有装成功。至于用哪个：你的项目用现有的 Node 26 就够了，不需要执着于安装 24。“安装失败”和“版本不对”是两件独立的事。 你这次的困惑，本质上是把 brew 安装中断（锁冲突） 和 当前生效的 Node 版本 混在了一起。在命令行里，一个命令失败不等于环境被破坏；which node 和 node --version 永远告诉你此刻真正在用的版本。学会分开看“操作结果”和“环境状态”，能帮你避免大量“我明明装了 A，为什么显示 B”的无效排查。
