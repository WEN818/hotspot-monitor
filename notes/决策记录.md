# 架构决策记录（ADR）

> 格式：决策 / 背景 / 备选方案 / 理由 / 代价。每做一个重要架构决定追加一条。

## ADR-001：存储用 SQLite，不用 Postgres/MySQL

- **决策**：单机 SQLite 文件库（hotspots.db）
- **背景**：5 天冲刺项目，单用户单进程读写，日增约 500 条
- **备选**：Postgres（需装服务、配用户权限）、MySQL（同左，更重）、CSV 文件（无查询能力）
- **理由**：Python 内置 sqlite3，零安装零运维；满足全部查询需求；不引入任何环境风险
- **代价**：多进程并发写入会锁库（本项目单进程顺序执行，不触发）；未来上多用户需迁移

## ADR-002：运行时模型用国产直连 API，不用 ChatGPT/Claude

- **决策**：分析层用 DeepSeek-V4-Flash（主力）+ GLM-4.7-Flash（免费备胎）
- **背景**：项目定时任务需长期无人值守运行；海外 API 在大陆网络环境不稳定
- **备选**：ChatGPT API、Claude API（能力上限更高）
- **理由**：关键路径必须物理稳定；DeepSeek 约 ¥20/月成本；GLM 免费额度覆盖调试期
- **代价**：分析文本质量上限略低于顶级海外模型（70 分目标下无实质影响）

## ADR-003：放弃 Twitter/X、Reddit 监控源

- **决策**：本期只做 HackerNews / GitHub Trending / 掘金 / 知乎 / B站
- **背景**：X 和 Reddit 在大陆需代理访问；抓取链路混入代理会引入浏览器桥登录态失效、定时任务依赖代理在线等三个故障点
- **备选**：强行接入（演示效果更"国际化"）
- **理由**：5 天工期内稳定性优先级高于源数量；架构上保留扩展位，未来加回只需改配置
- **代价**："跨平台"的国际维度只剩 HN/GitHub，报告需在"未来工作"中说明

## ADR-004：Hermes Agent 设半天接入封顶，失败即降级

- **决策**：Day 3 上午为 Hermes 接入时限；失败则降级为"Python 脚本直接调 LLM API 规划 + OpenCLI 执行"
- **背景**：Hermes 首次配置需 2-4 小时，是项目最大不确定性；个人编程基础较弱
- **备选**：不限时硬啃 Hermes
- **理由**：降级方案业务能力等价（规划层只是变薄）；保证 Day 4 联调时间不被吞掉
- **代价**：报告需如实呈现"原方案 vs 降级方案"对比（评审视角下反而是工程判断力加分项）
