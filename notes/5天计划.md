# hotspot-monitor 5 天冲刺计划

> 原则：砍掉非核心功能；最大风险（Hermes 配置 2-4 小时）后置到 Day 3；每天设硬性验收线；23:00 收工。
实际上可能只有3天半的有效时间，下面的计划需要做适当压缩。

## 砍掉的内容（写进报告"未来工作"章节）

- Twitter/X、Reddit 监控源
- 看板历史趋势图表（降级为"今日热点 + 分析摘要"两页）
- Hermes 技能自生长演示(如果你觉得有机会做，请适当加入这个内容，但是还是把先完成一个完整的系统为第一优先级)

## Day 1：环境 + OpenCLI 抓取 + SQLite 落库

- 上午：注册 DeepSeek/智谱平台领 API Key；安装 Python 3.11+ / Git / Node.js 20+ / Trae；git init + venv + 首个 commit
- 下午：`npm install -g @jackwener/opencli` → `opencli doctor` → `opencli list` 输出存 notes/ → 跑通第一个无需登录的源（HN / GitHub Trending）
- 晚上：写 fetch.py（subprocess 调 opencli → 解析 JSON → 存 SQLite），失败容错
- **验收线**：SQLite 中 ≥3 个平台、≥30 条今日热点数据
- **降级预案**：连 1 个源都没数据 → 放弃直连，浏览器桥 + 手动导出先保证有数据，OpenCLI 调试挪到 Day 4 缓冲

## Day 2：AI 分析层

- 写 analyze.py：读当日 posts → 喂给 DeepSeek-V4-Flash → 主题聚类 + 中文摘要 + 跨平台共振判断
- 调试期用免费 GLM-4.7-Flash，跑通后切 DeepSeek
- **验收线**：输入昨天数据，命令行输出一份能读的中文分析报告

## Day 3：Hermes 接入（半天封顶）+ Streamlit 看板

- 上午：按 notes/hermes调研.md 接入 Hermes Agent，写"监控"skill，目标：说一句自然语言 → Hermes 触发 fetch.py
- **失败降级**（封顶半天）：改用"Python 脚本直接调 LLM API 做规划 + OpenCLI 执行"，报告如实写原方案与降级方案对比
- 下午：Streamlit 看板（今日热点列表 + 分析摘要两页）
- **验收线**：看板能展示数据；Hermes 至少能手动触发一次抓取（或降级方案跑通）

## Day 4：端到端联调 + cron 定时

- 自然语言 → 规划 → 抓取 → 分析 → 看板 全流程跑通
- cron 定时任务：每日自动抓取 + 分析
- 剩余时间全部留给修 bug（联调必出问题，正常）
- **验收线**：全流程无人值守跑通一遍

## Day 5：容错 + 报告 + 演示 + 缓冲

- 容错：单平台失败跳过并记录；Hermes 危险动作人工确认边界
- README、架构图（Excalidraw）、demo 录屏（现场说一句自然语言让它跑——最抓人的演示瞬间）
- 全天作为缓冲，前几天欠债今天还

## 三条纪律

1. 任何环节卡 40 分钟必求助（先 Trae Builder，再 DeepSeek/Kimi），报错原文 + 执行的命令一起贴
2. 好的 AI 回答 30 秒内复制进 notes/ 并 git commit
3. AI 给的任何 CLI 命令先手动试跑再进脚本；版本/参数以官方文档为准
