# hotspot-monitor：3.5 天执行计划

> 项目目标：优先保证核心链路完整跑通，达到课程项目 70 分目标。  
> 时间安排：3 个完整工作日＋最后半天交付；完整工作日 23:00 前收工。  
> 核心链路：自然语言需求 → Hermes Agent（或降级方案）→ OpenCLI 抓取 → SQLite 入库 → AI 分析 → Streamlit 看板。  
> 本版原则：先完成最低可运行版本，再补稳定性与交付材料；任何非核心功能都不能挤占联调和演示时间。

## 一、最终交付标准

到第 4 天中午，至少完成以下内容：

- [ ] 用户输入一句自然语言，可以触发一次抓取；Hermes 接入失败时，使用降级方案并如实记录。
- [ ] 至少 3 个平台、合计至少 30 条热点数据写入 `hotspots.db`。
- [ ] AI 能基于最新一批数据生成可读的中文报告，包含主题聚类、摘要和跨平台共振判断。
- [ ] Streamlit 能展示“今日热点”和“分析摘要”，并支持按平台筛选。
- [ ] 单个平台失败不会中断其他平台，错误信息有日志可查。
- [ ] cron 或等效定时方式成功自动执行过一次完整流程。
- [ ] 完成 README、架构图、演示录屏及关键 ADR 记录。

## 九、MacBook 环境清洁与账号安全

- Python 依赖只装进项目 `.venv`，不要使用 `sudo pip`，也不要污染系统 Python。
- OpenCLI 优先采用官方支持的项目级安装方式；如确需全局 npm 安装，不使用 `sudo`，并记录安装命令以便之后卸载。
- API Key 只放本地 `.env`；`.env`、浏览器登录信息、数据库和日志必须加入 `.gitignore`，仓库只提交不含真实值的 `.env.example`。
- AI 给出的命令先看清作用再手动试跑，不执行来源不明的 `curl ... | sh`，不把未验证命令直接写入 cron。
- 使用浏览器桥时只复用必要的知乎/B站登录态；录屏、截图和 Git 提交前检查是否暴露 Cookie、头像、私信或其他个人信息。
- 每个工作块结束执行一次小提交；大改前先提交可运行版本，比手动复制大量“最终版2”文件夹更安全。
- 项目结束后，先退出虚拟环境，再删除不再需要的 `.venv` 和本地依赖；确认没有 cron 任务继续调用旧目录。
