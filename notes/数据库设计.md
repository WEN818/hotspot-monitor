# 数据库设计：hotspots.db

## 一、设计约束

- 单用户、单机、SQLite（ADR-001）
- 日增数据约 500 条以内
- 需支持按平台、按日期查询
- 某平台抓取失败时数据缺失可容忍（该批次该平台无记录，不中断整体）

## 二、表结构

### posts 表（热点条目，唯一业务表）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PRIMARY KEY AUTOINCREMENT | 自增主键 |
| platform | TEXT NOT NULL | 平台标识，如 hackernews / github / juejin / zhihu / bilibili |
| title | TEXT NOT NULL | 热点标题 |
| url | TEXT | 链接（可空，防个别源无链接时插入失败） |
| heat | INTEGER | 热度值（分数/热度/播放量等统一存整数，允许为空） |
| fetched_at | TIMESTAMP DEFAULT CURRENT_TIMESTAMP | 抓取时间戳，区分批次；定时任务每天产生新批次 |

建表 SQL（开发中由 Trae 生成，此处为基准）：

```sql
CREATE TABLE IF NOT EXISTS posts (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    platform TEXT NOT NULL,
    title TEXT NOT NULL,
    url TEXT,
    heat INTEGER,
    fetched_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

## 三、批次语义

- 每次 fetch.py 运行 = 一个批次，所有该批次记录共享相近的 fetched_at
- 分析层每次取"最新一批"：按 fetched_at 最大值过滤
- 查询示例：SELECT * FROM posts WHERE fetched_at >= date('now') 取今日数据

## 四、容错约定（写入 fetch.py）

- subprocess 调 opencli 加超时（建议 120 秒/平台）
- 单平台解析失败：打印错误日志（平台名 + 报错 + 原始输出前 500 字），继续下一平台
- 全部平台失败：进程退出码非零，cron 场景下可从日志定位

## 五、未来扩展（不在本期）
